# ゲームのプレイ回数

## 集計ルール

- ゲストを含む全プレイヤーの、ゲーム開始回数を共有する。同じセッションでも、新しい開始・再挑戦は毎回加算する。
- ゲーム選択カード、科目内のゲーム選択、国別のゲーム一覧・学年マップ・基礎レッスン入口に表示する。
- 同じゲームの学年・難易度違いは共通のゲームキーに集計する。人数やユニークユーザー数ではない。
- ホーム閲覧、回答、遊び方の再表示は加算しない。過去の実績から架空の回数は生成しない。
- 1,000回以上はK、1,000,000回以上はM、1,000,000,000回以上はB。小数第1位まで切り捨て、補助ラベルには正確な回数を残す。
- 未取得時は「—」。オフラインの開始はクラウド集計に含まれず、復帰後の遡及送信は行わない。通信障害でゲームを停止しない。

## データとAPI

`GET /api/play-counts?keys=...` は許可リスト内のゲームを最大100件取得する。`POST /api/play-counts` は `{key,eventId}` を受け取る。ログインは不要だが、許可されたOriginとJSON形式が必要。

D1の `game_play_events` への挿入トリガーで `game_play_counts` を原子的に加算する。別々のクリックには別のUUIDを発行し、通信再送だけ同じUUIDを使う。イベントの重複排除期間は24時間、合計回数は永続保存。ユーザーID・IP・端末指紋は記録しない。

Origin検証はブラウザのクロスオリジン送信を制限するもので、ボットによる数字の水増しを完全に防ぐ仕組みではない。公開運用時はCloudflare側の監視・WAFも併用する。

## リリースと検証

本機能の公開には、既存のマイグレーションに続いて `migrations/0010_game_play_counts.sql` を本番D1へ適用し、Workerとビルド済みフロントエンドを更新する必要がある。静的ファイルのみのローカルサーバーでは共有集計APIを利用できない。

- `node tests/test_play_counts.mjs`：実際のローカルD1で並行加算、ゲスト利用、再送、期限、入力検証。
- `node tests/test_play_counts_browser.mjs`：Playwrightによる表示・繰り返し開始・説明再表示・モバイル幅の検証。`BROWSER_CHANNEL` でChrome/Edgeを選択できる。
- `node tests/test_e2e_runner.js`：既存ゲームの回帰テスト。
- `node scripts/build.mjs`：配信用ファイルを生成。
