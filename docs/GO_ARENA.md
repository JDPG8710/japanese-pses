## 范围与入口

用户目标 → 独立休闲棋室（不绑定年级、学科、课程进度）→ 9 路围棋 → `/arena.html` → 规则、真实房间 API 与浏览器测试。

首页、国家选择页、中日英介绍页、小游戏页提供入口。当前仅围棋，不显示尚未实现的国际象棋按钮。

- 游客：服务端签发 HttpOnly、SameSite=Strict、有效期 7 天的临时身份 Cookie；清除身份后无法取回座位。
- 登录：复用 Google 会话，公开房间显示代号，不发送账户姓名、邮箱或账户 ID。最近 20 局可回看。
- 邀请：随机 UUID 链接，明确点击加入；满员拒绝第三人；双方准备后开始。
- 匹配：等待 20 秒后提示电脑对战；预先勾选后可自动转换。邀请房间提供另开页面练习，原房间继续等待。
- 电脑：入门、简单、中等、困难，共享服务器规则。轻量战术引擎，难度由提子、逃子、对手应手搜索区别，不代表段位。
- 触屏：点击一次交叉点立即落子；桌面与平板并排布局，手机单列。

## 规则契约

9×9，黑先，白贴 7.5 目，每人 15 分钟绝对用时，断线不暂停。服务器检查轮次、合法落子、提子、自杀禁入与全局同形禁着（positional superko；停一手除外）。

连续两次停一手进入计分。任一玩家可标记整组死子；每次修改取消双方之前的确认。双方同意后按活子与单方围住的空点计分。争议时恢复行棋。电脑练习接受用户的死子标记，不提供自动死活裁判。认输、超时也可结束。不关联课程金币或排名。

## 后端

### 人机准入保护

统一的 `ai-capacity:v1` Durable Object 原子分配名额，真人局不占名额。默认 `GO_AI_MAX_ROOMS=8`，`GO_AI_MAX_UNITS=16`；入门/简单每局 1 单位，中等 2 单位，困难 4 单位，所以全困难时最多 4 局。每个登录/游客身份同时只允许一局人机，重复请求返回原房间链接。准备中的房间也占名额。

任一预算已满、最近单步搜索耗时达到 `GO_AI_SLOW_MS=250` 毫秒（暂停准入 60 秒），或准入服务不可用时，新人机请求返回 HTTP 503 / `AI_BUSY` 及 Retry-After。计算耗时是应用观察到的墙钟时间，不是平台全局 CPU 利用率。当前阈值是保守保护配置，不是压测证明的容量。任一容量设为 0 可关闭新的人机准入，现有对局可继续。

名额使用 120 秒租约，活跃房间最多每 60 秒续约；结束、取消、过期时释放。准入成功但创建响应不确定时保留租约至过期，避免误释放导致超额。续约服务不可用时不执行 AI 搜索，稍后重试；丢失租约的旧房间停止计算并过期，不能与已重新分配的名额同时运行。小游戏自动转电脑也走同一准入接口。`node tests/test_go_capacity.mjs` 另有 12 项真实 DO 并发、权重、释放、过期、熔断恢复测试。

- `worker/arena-entry.mjs`：部署入口，导出原 API Worker 与两个 Durable Object 类。
- `GoRoom`：每局一实例，SQLite 保存完整状态；无跨请求内存正本。动作 HTTP 请求逐次验证身份与 revision；WebSocket 只推送，不接受客户端直接改棋局。
- `GoLobby`：匹配队列；另以请求 IP 哈希命名独立限流实例。房间落子不经过全局匹配实例。
- 空房、准备、计分阶段 30 分钟过期；结束／过期房间约 24 小时后清理，读取终局会延后清理。D1 归档失败时保留房间，并通过 alarm 重试。
- `0012_go_games.sql`：棋谱、结果、对战类别以及登录玩家关联；电脑和真人分别记录 mode。
- 原 Pages `/api/*` Service Binding 原样转发，包括 WebSocket Upgrade。
